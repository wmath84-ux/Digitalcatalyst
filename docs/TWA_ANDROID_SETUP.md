# Eduvora Android TWA — Setup & Play Store Submission

This document is the **step-by-step guide** for taking the Eduvora PWA
and publishing it as a **Trusted Web Activity** on the Google Play
Store, with **guaranteed-delivery notifications** (FCM + AlarmManager).

Everything technical is already wired up in this repository. The
remaining steps are operational: create a Firebase project, generate
signing material, fill in the SHA-256 fingerprint, and submit the
AAB to the Play Console.

> **Why this exists** — the previous setup used Web Push only. Web
> Push on Android Chrome is unreliable (battery optimisers, doze
> mode, OEM kill background apps), so reminders arrived 5 minutes to
> several hours late. The TWA + FCM + AlarmManager stack delivers
> reminders at the **exact wall-clock time** even when the app is
> closed, the device is locked, and battery saver is on. See
> `api/_lib/fcm.ts` and `src/utils/capacitorBridge.ts`.

## 1. What the codebase already does (you don't need to write any code)

| Concern | Where it lives | What it does |
|---|---|---|
| Capacitor config | `capacitor.config.ts` | Sets appId, webDir, Android scheme. |
| WebView wrap | `android/` | The whole Android project, generated by `npx cap add android`. |
| Manifest | `android/app/src/main/AndroidManifest.xml` | Adds POST_NOTIFICATIONS, USE_EXACT_ALARM, RECEIVE_BOOT_COMPLETED, Digital Asset Links. |
| FCM client | `src/utils/capacitorBridge.ts` | Registers for FCM, schedules local alarms, deep-links taps. |
| FCM server | `api/_lib/fcm.ts` | `admin.messaging().send()` fan-out, dead-token pruning. |
| Token registration | `api/push/send.ts` (action=`fcm-register`) | Writes `users/{uid}/fcmTokens/{hash}`. |
| Cron fan-out | `api/cron/subscription-renewals.ts` | My Day reminders + content announcements also reach FCM. |
| Firestore rules | `firestore.rules` (`/fcmTokens/{tokenId}`) | Owner-scoped, admin-readable. |
| Build scripts | `package.json` | `npm run android:assemble:debug`, `npm run android:bundle:release`. |
| Tests | `tests/pushTwaFcmContract.test.mjs` | 27 contract tests pin the wiring. |

## 2. Firebase project setup (one-time, ~15 min)

### 2.1 Create the project

1. Go to <https://console.firebase.google.com>.
2. Click **Add project** → name it `Eduvora` → continue.
3. Disable Google Analytics (you don't need it) → **Create project**.

### 2.2 Add an Android app

1. In the project overview, click the **Android** icon.
2. **Android package name**: `app.eduvora.shop` (matches
   `capacitor.config.ts`).
3. **App nickname**: `Eduvora`.
4. **Debug signing certificate SHA-1**: skip for now; the release
   SHA-256 is what matters for Digital Asset Links.
5. Click **Register app** → **Download google-services.json**.
6. Drop the file at `android/app/google-services.json`. **Never
   commit it** (already covered by `.gitignore`).

### 2.3 Enable Firebase Cloud Messaging

1. In the left rail, go to **Engage → Messaging** (or **Run →
   Cloud Messaging**).
2. The first run auto-creates a service account. Nothing to click.

### 2.4 Get a service account JSON for the server

1. **Project settings** (gear icon) → **Service accounts**.
2. Click **Generate new private key** → **Generate key**.
3. Save the JSON file. You'll convert it to base64 in step 4.

### 2.5 Add Firebase to the Vercel project

The same Firebase project backs both the client (Android TWA) and the
server (FCM Admin SDK). On Vercel:

1. Project → **Settings** → **Environment Variables**.
2. Add three variables:
   - `FIREBASE_SERVICE_ACCOUNT_BASE64` — paste the base64 of the
     service account JSON from step 2.4. (`base64 -w 0 serviceAccount.json`)
   - `WEB_PUSH_VAPID_PUBLIC_KEY` — already set; keep as is.
   - `WEB_PUSH_VAPID_PRIVATE_KEY` — already set; keep as is.
3. Redeploy so the new env var is picked up.

## 3. Generate the release signing keystore (one-time, ~5 min)

The Play Store requires every AAB to be signed with a key **that you
own** (Google keeps a copy too). The local debug key cannot publish.

```bash
# From the project root:
cd android/app
keytool -genkey -v \
  -keystore eduvora.keystore \
  -alias eduvora \
  -keyalg RSA -keysize 2048 -validity 10000
# Answer the prompts. Pick a STRONG password and remember it.
# Answer "yes" when asked "Is <your name> correct?".
```

Add to your shell (or `~/.gradle/gradle.properties` so they're not
session-bound):

```bash
export EDUVORA_KEYSTORE_FILE="$(pwd)/eduvora.keystore"
export EDUVORA_KEYSTORE_ALIAS=eduvora
export EDUVORA_KEYSTORE_PASSWORD="<the password you picked>"
export EDUVORA_KEY_PASSWORD="<the same password>"
```

> **Never** commit the keystore or the password. Both are covered
> by `.gitignore`. Back the keystore up to a password manager
> separately — losing it means losing the ability to publish updates.

### Get the SHA-256 fingerprint

```bash
keytool -list -v -keystore android/app/eduvora.keystore -alias eduvora
```

Copy the **SHA256** line. You'll use it in steps 5 and 6.

## 4. Build the release AAB

```bash
cd /home/user/Digitalcatalyst
npm run build                  # vite build → dist/
npx cap sync android           # copies dist/ into android/app/src/main/assets/public
cd android
./gradlew bundleRelease        # produces app/build/outputs/bundle/release/app-release.aab
```

The first build takes ~5 minutes (Gradle downloads everything).
Subsequent builds are ~30 s.

The AAB lives at `android/app/build/outputs/bundle/release/app-release.aab`.
That is the file you upload to the Play Console.

## 5. Digital Asset Links (one-time per origin)

The TWA only launches full-screen after Google verifies the app
belongs to `eduvora.shop`. Two pieces must match:

### 5.1 Edit `android/app/src/main/res/values/strings.xml`

Replace the placeholder with your SHA-256 fingerprint from step 3:

```xml
<string name="asset_statements" translatable="false">
    [{
        \"relation\": [\"delegate_permission/common.handle_all_urls\"],
        \"target\": {
            \"namespace\": \"android_app\",
            \"package_name\": \"app.eduvora.shop\",
            \"sha256_cert_fingerprints\": [
                \"AA:BB:CC:DD:...your_sha256_here...\"
            ]
        }
    }]
</string>
```

### 5.2 Serve the matching JSON at `https://eduvora.shop/.well-known/assetlinks.json`

The Play Console (and the on-device TWA) will fetch this file to
verify the link. Add it to the Vercel project:

**`public/.well-known/assetlinks.json`**

```json
[{
  "relation": ["delegate_permission/common.handle_all_urls"],
  "target": {
    "namespace": "android_app",
    "package_name": "app.eduvora.shop",
    "sha256_cert_fingerprints": [
      "AA:BB:CC:DD:...your_sha256_here..."
    ]
  }
}]
```

Vercel serves files from `public/` at the site root, so this URL
becomes `https://eduvora.shop/.well-known/assetlinks.json` after
the next deploy.

Verify it works with Google's tool:
<https://developers.google.com/digital-asset-links/tools/generator>

## 6. Play Store listing (one-time per app)

### 6.1 Create the Play Console account

1. Go to <https://play.google.com/console>.
2. Pay the **$25 one-time** developer registration fee.
3. Accept the developer agreement.

### 6.2 Create the app

1. **All apps** → **Create app**.
2. App name: `Eduvora`. Default language: English.
3. App / game: **App**. Free / paid: **Free**.
4. Accept the declarations → **Create app**.

### 6.3 Fill in the store listing

- **App name**: `Eduvora`
- **Short description** (80 chars):
  > Study plans, notes, courses and reminders — all in one place.
- **Full description** (4000 chars):
  > (Write your own; mention the offline-first PWA, My Day reminders,
  > revision tests, and that it's free.)
- **App icon**: 512×512 PNG, no transparency. (Use the same
  `public/icons/icon-512x512.png` already in the repo, or upload a
  custom one.)
- **Feature graphic**: 1024×500 PNG/JPG.
- **Screenshots**: at least 2 phone screenshots (PNG or JPG). Take
  these on a real device or via `npx cap run android` → record a
  screencast.

### 6.4 Set up the release

1. Left rail → **Release** → **Production** → **Create new release**.
2. Upload `app-release.aab` from step 4.
3. Add release notes:
   > First release of the Eduvora TWA. Same PWA, now with
   > guaranteed-delivery reminders and offline access.
4. **Review and roll out**.

Google's review takes 1-7 days. After approval, the app shows up on
the Play Store within a few hours.

### 6.5 Promote the install link

Add a Play Store badge to the PWA so users can install the Android
app. The Play Store URL is:

```
https://play.google.com/store/apps/details?id=app.eduvora.shop
```

A simple install banner in the PWA:

```html
<a href="https://play.google.com/store/apps/details?id=app.eduvora.shop"
   class="...">📱 Install the Eduvora Android app</a>
```

## 7. Testing the build on a real device

Before submitting to the Play Store, test locally:

```bash

cd /home/user/Digitalcatalyst
npm run android:run
```

This builds a debug APK, installs it, and launches it. Verify:

- [ ] The app opens at `https://eduvora.shop` (not a Custom Tab).
- [ ] Sign in with a real account.
- [ ] Allow notifications when prompted.
- [ ] Add a My Day task with a time 1-2 minutes in the future.
- [ ] Background the app and lock the screen.
- [ ] The notification fires at the exact scheduled time.
- [ ] Tapping the notification opens the app at the right deep link.

If all of the above work, the build is ready for the Play Store.

## 8. After publishing

### 8.1 Monitor the FCM service account

If you ever rotate the service account JSON (recommended yearly):

1. Download a new private key from Firebase.
2. Base64-encode it.
3. Update `FIREBASE_SERVICE_ACCOUNT_BASE64` on Vercel.
4. Redeploy.

### 8.2 Rotate the signing key (only if compromised)

Google Play App Signing lets you upload a new key without breaking
existing installs. See:
<https://support.google.com/googleplay/android-developer/answer/9842756>

## 9. FAQ

**Q: Does the same AAB work for the existing web app users?**
A: Yes. The TWA loads `https://eduvora.shop`, so users keep their
accounts, purchases, My Day data, etc. The Android app is just a
native shell around the existing PWA.

**Q: Will Web Push still work?**
A: Yes. The dual-transport fan-out (Web Push + FCM) is in
`api/push/send.ts`. Desktop web users still get Web Push; Android
TWA users get FCM. Either transport being down does not block the
other.

**Q: What happens if I never set up FCM / never publish the app?**
A: Everything still works on the web. The FCM dispatcher returns 0
when the service account is missing, and the Capacitor bridge is a
no-op on non-Android platforms. The only thing the user loses is
the guaranteed-delivery guarantee on Android, which is exactly the
problem we're solving.

**Q: Can I use an existing Android app?**
A: Yes — copy the manifest, gradle and res/ entries from
`android/app/src/main/` into your existing project. The web-side
changes (`src/utils/capacitorBridge.ts`, the FCM helper, the
main.tsx wiring) are the actual work; the Android project is just
the host.

**Q: How do I update the app after the first release?**
A: `npm run android:bundle:release` produces a new AAB with a
higher `versionCode` (set in `android/app/build.gradle`). Upload
it to the Play Console under **Production** → **Create new release**.

## 10. Troubleshooting

| Symptom | Likely cause | Fix |
|---|---|---|
| "App not installed" on a real device | Wrong signing config | Re-run `./gradlew assembleDebug`; the dev keystore auto-signs. |
| Notification doesn't fire at the right time | Battery saver is killing AlarmManager | Add the app to the battery-saver allowlist; or accept the `<1 min` slip. |
| Push arrives but tapping does nothing | URL in the FCM payload is wrong | Check `api/push/send.ts` passes the right `url` per notification kind. |
| Play Store rejects the AAB | `versionCode` already used | Bump `versionCode` in `android/app/build.gradle`. |
| Asset Links verification fails | SHA-256 mismatch | Re-run `keytool -list` and make sure the strings.xml AND assetlinks.json match exactly. |
| "google-services.json not found" at build time | File not at the right path | `android/app/google-services.json` is the path. Add it then `npx cap sync android`. |
